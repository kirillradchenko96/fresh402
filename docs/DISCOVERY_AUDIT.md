## Coinbase Bazaar: eligibility is not indexing

The public merchant API and filtered search each returned one resource: **/v1/check**. Its price is still 5000 atomic USDC, but its description, service name and schema are older than the live v2 challenge. **/v2/extract** and **/v2/smart-diff** were absent from the complete merchant result (pagination total=1). They are discoverable through Fresh402's own OpenAPI, MCP and manifest and are **technically eligible based on locally valid advertised extensions**, not verified indexed by CDP.

CDP documents asynchronous indexing after successful settlement carrying both resource and Bazaar extension, public search/merchant discovery, and a nonpaying validation endpoint. A validator or HTTP 402 success does not prove catalog inclusion. No payment was made to force indexing. See [Get discovered](https://docs.cdp.coinbase.com/x402/seller/get-discovered) and [public discovery interfaces](https://docs.cdp.coinbase.com/x402/buyer/discover-services).

The official nonpaying validator was also tested with its documented resource/method request. Check returned valid=true and simulation outcome accepted. Extract and Smart Diff returned valid=false, probe status 400 and the exact reason "endpoint failed preflight checks": the validator sent no required input (missing url or watch_id), so input validation preceded the 402 challenge. Direct unsigned requests with valid input returned 402 and valid Bazaar blocks for both products. This default-probe result is a separate discoverability compatibility blocker; it is not evidence that those products are indexed or that paid calls succeeded. Production input validation was not changed to accommodate it.

The current [CDP SDK request type](https://github.com/coinbase/cdp-sdk/blob/main/typescript/packages/cdp-sdk/src/openapi-client/generated/coinbaseDeveloperPlatformAPIs.schemas.ts) exposes only resource and method for this validator, with no request-body field. Thus a supported body-bearing probe or provider intervention is needed to assess these POST contracts through that interface. A successful future paid call alone must still be followed by public index verification. x402scan's [official discovery specification](https://github.com/Merit-Systems/x402scan/blob/main/docs/DISCOVERY.md) also documents skipped routes when empty probes return 400; its own live refresh registered Extract, but not Smart Diff.
